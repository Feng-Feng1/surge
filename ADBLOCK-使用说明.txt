Surge 去广告手动更新版 6.5.0

已经安装的用户
在 Surge 点原模块的“更新模块”，确认版本以 6.5.0-manual 开头即可。订阅地址不变：
https://raw.githubusercontent.com/Feng-Feng1/surge/refs/heads/main/AdBlock-AllInOne.sgmodule
重写、脚本和 HTTPS 解密及证书信任需要保持启用。此轮按 Surge iOS 5.22.1 的能力核验，不引入要求 5.23 的模块内 Ruleset 功能。

更新方式
GitHub 每天北京时间 04:17 准备新快照（实际运行可能延迟），你在 Surge 更新模块后应用新资源；不用电脑生成文件。
总模块及仓库独立模块的自有脚本固定到内容哈希路径，外部 raw 脚本固定原作者 Git commit。WeatherKit 保持现有 v3.3.2 发布版与参数，其发布附件未由本构建器重新下载及哈希核验。
Surge 周期获取同一脚本地址不会改选较新的代码；规则集设置 update-interval=-1。是否自动应用模块取决于 Surge 自身设置，模块没有虚构禁用后台检查的参数。
首次下载和新版本资源仍需要联网；资源下载失败时可在 Surge 外部资源页重试。

安装模块的关系
通常只需原去广告总模块。独立的 YouTube、优酷、贴吧、瓜子、腾讯等模块供单独使用；同类模块同时启用时，Surge 每次请求/响应只执行第一个匹配脚本，不会叠加执行。
不要靠同时安装两份相同功能的模块加强清理；已安装用户只更新原来使用的模块即可。

维护仓库
.adblock/baseline 是总模块和共享脚本的维护源；.adblock/modules 是其余模块的维护源。根目录模块是构建后发布给 Surge 的文件，不要只改生成文件后让下一轮构建覆盖。
其余根目录 JS/TXT 脚本是维护源，工作流会将被模块引用的自有脚本生成内容哈希副本。所有模块模板都会进入同一构建及格式校验；脚本、模板和维护程序变更会触发后台检查。
工作流先执行转换保障及运行回归，再准备快照和检查全部模块，最后一次提交发布；检查失败不会提交半成品，也不会强制覆盖 main。
未知复杂 AdGuard 例外、有效 DNS 重写、错误网页/404、源码或哈希校验失败会停止更新。旧的已发布版本继续可用。

回退
Rollback/6.4.0 保存本轮修改前的完整总模块及共享脚本，Rollback/6.3.1 保留更早版本；构建只核验它们，不改写历史文件。
旧 Resources/AdBlock 哈希文件保留，不自动删除，否则旧版模块的引用可能失效。

能力与核验范围
按 Surge 官方文档核对配置、匹配顺序、响应体和二进制/响应头接口，并做合成数据的成功、失败及更新回归。
这是源码/离线检查及 GitHub 构建核验，不能代替你的手机测试。新广告接口、应用缓存或原生布局变化仍可能需要针对性修复。
AdGuard 转换使用可表达的 DNS 主机子集，包含广告与追踪；条件规则、CSS/ExtendedCss、浏览器 scriptlet、DNS 应答重写及 CNAME 链过滤无法全部等价转换为 Surge 原生 App 容器处理。
仓库不会上传 HAR、聊天截图、证书或私人令牌。原始 DNS 源、许可证、来源固定值及维护源码均保留。
