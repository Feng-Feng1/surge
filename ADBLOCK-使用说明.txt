Surge 去广告总模块 6.6.0

已安装的用户
在 Surge 中打开原去广告模块，点“更新模块”应用新版。模块地址保持不变：
https://raw.githubusercontent.com/Feng-Feng1/surge/refs/heads/main/AdBlock-AllInOne.sgmodule
HTTPS 解密、证书信任、重写和脚本功能需按原配置启用。

更新方式
GitHub 工作流每天北京时间约 04:17 获取上游并准备快照；上游规则或脚本新增后，进入下一次已验证快照。你只需在 Surge 手动更新总模块。
工作流完整合并秋风 Surge 模块的 [Rule] 区段，以及奶思 Surge 模块的 [Rule]、[URL Rewrite]、[Script] 区段。奶思规则仅取自 blockAds.module，不再调用单独的 rejectAd.list。规则、重写和脚本都会去重；没有按具体广告条目维护的静态白名单。
奶思的 [Body Rewrite]、[Map Local]、[Header Rewrite] 和 [MITM] 区段不导入。自维护功能及兼容规则保留在总模块内，优先于普通拦截规则；秋风纯广告规则按 Surge 的 pre-matching 优先级处理。
外部脚本固定到已校验的上游 Git commit；规则文件使用内容哈希。Surge 周期获取同一固定地址不会自动换到未来代码。WeatherKit 继续使用原 v3.3.2 发布附件。
遇到上游格式变化、未知规则参数或冲突时，工作流会失败并保留当前已发布模块，不会静默漏掉新内容。

本轮调整
• 移除活动总模块中的 AdGuard DNS 规则层及旧 LiveMerge/可莉合并逻辑。
• 将秋风完整规则与奶思 blockAds.module 中的规则、URL Rewrite、Script 接入每日构建，不再调用奶思分散规则列表或用逐条白名单筛选新增内容。
• 合并重复规则和重写；同一请求命中的重复脚本保留先匹配的自维护规则，避免执行两次。
• 保留已有的 Bilibili、腾讯视频、闲鱼、地图及其他自维护规则和脚本。

安装关系与性能
通常只需使用原去广告总模块。独立 YouTube、优酷、贴吧、瓜子、腾讯等模块供单独使用；避免同时启用重复功能的模块。
大型域名规则通过 Surge RULE-SET 缓存和索引，模块不再加载 AdGuard DNS 的十万级转换列表。奶思当前上游包含较多 URL Rewrite 和 Script 规则；具体合并条数见 AdBlock-Update.json。设备端的页面速度仍需在 Surge 更新后实测。

维护仓库
.adblock/baseline 是总模块与共享脚本的维护源；.adblock/modules 是其他模块的维护源。根目录模块为生成后的 Surge 文件。
每次构建都会获取上游完整指定区段并固定 commit；新出现的未知区段或格式会停止发布以待修正。旧 Resources/AdBlock 哈希文件保留，避免历史模块或回退版本失效。
工作流先运行合并、脚本语法、运行回归、模块格式和资源完整性检查，全部通过后才提交生成文件。

回退与核验
Rollback/6.4.0 和 Rollback/6.3.1 是历史快照，构建只核对其完整性，不改写它们。新规则尚未在用户设备上验证；上游变化或应用原生界面变化仍可能需要专门修复。
仓库不会上传 HAR、聊天截图、证书或私人令牌。
